# dMAT Trainer

Unlimited practice for the three **dMAT Core Module** task types, with a
per-question stopwatch and cross-device progress tracking.

> **Unofficial project.** Not affiliated with, endorsed by, or connected to
> g.a.s.t. or the TestDaF-Institut. It contains no official examination
> material — every question is generated by the algorithms in this repository.
> Always treat the official preparatory materials as authoritative.

The official preparatory materials ship only six exercises per task type — two
each at low, medium and high difficulty, which is nowhere near enough volume to
build the pattern recognition the test rewards. This app **generates** questions
in the same formats instead, so you can drill them indefinitely at the exam's
pace of roughly 75 seconds per question.

| Task type | Format |
| --- | --- |
| **Figure Sequences** | 4 × 4 matrix. Matrices 1–4 shown, 5 and 6 hidden. Three response options for Image 1 and three for Image 2. |
| **Mathematical Equations** | A system of equations over letters A–D. Each letter is an integer 1–20, with exactly one solution. |
| **Latin Squares** | 5 × 5 grid, letters A–E, one question mark. Pick the letter that belongs there. |

Every subtest is 20 questions in 25 minutes, and notes are not allowed.

## Setup

### 1. Install

```bash
npm install
```

### 2. Create the Supabase project

1. Create a free project at [supabase.com](https://supabase.com).
2. Open **SQL Editor** and run the contents of
   [`supabase/migrations/0001_init.sql`](supabase/migrations/0001_init.sql).
   This creates the `attempts` and `exam_sessions` tables and — importantly —
   turns on Row Level Security so the data is only ever visible to you.
3. Under **Project Settings → API**, copy the project URL and the `anon` key.

### 3. Configure

```bash
cp .env.example .env.local
```

Fill in `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

Both values are safe in the browser: RLS is what protects the rows, not secrecy
of the anon key.

### 4. Run

```bash
npm run dev
```

Open <http://localhost:3000>, create an account, and start practising.

## Deploying

Push the repo to GitHub, then import it at [vercel.com](https://vercel.com).
Add the same two environment variables in **Project Settings → Environment
Variables** and deploy.

Sign in once on each device and your counts, accuracy and times follow you.
On a phone, use **Add to Home Screen** — the app ships a web manifest and runs
standalone with full functionality.

If a question is answered while offline, the attempt is buffered in
`localStorage` and flushed the next time the app loads with a session.

Note that questions are generated in your browser and stored only as seeds, so
nothing about what you practised leaves your own Supabase project.

## Using it

- **Practice** — endless single questions with instant feedback and a full
  solution path. Difficulty is Low / Medium / High / Random. The stopwatch counts
  up and turns amber past the 75 s exam pace.
- **Exam** — 20 questions against a 25:00 countdown, no feedback until you
  finish. It auto-submits at zero. Per-question times are still recorded
  individually, and the results page lists every question with its solution.
- **Rules** — what each task type asks, the constraints every question obeys,
  worked examples and the timing. Also available collapsed on every question page.
- **Replay** — every question is fully determined by its seed (e.g. `FS-H-7K3QM2`).
  Copy a seed from any question or from the dashboard, paste it here, and you get
  that exact question back — same figures, same options, same order.
- **Dashboard** — questions practised per task type, accuracy, median time
  against the exam pace, a difficulty breakdown, daily volume, and recent
  exam sets.
- **Buy me a coffee?** — an optional tip page with a UPI QR code, the UPI ID
  and a contact address. It unlocks nothing; see
  [Setting up the support page](#setting-up-the-support-page).

## How the questions are generated

All generation is **client-side and deterministic from a seed**. The database
stores attempt records only — never the questions themselves — because a seed
regenerates the exact question on demand.

Nothing inside `lib/generators/` calls `Math.random()`; every draw goes through
the seeded PRNG in [`lib/rng.ts`](lib/rng.ts).

- **`lib/generators/figureSequences.ts`** — places one figure at a time and
  simulates the whole series, so "figures cannot overlap" and "figures cannot
  leave the matrix" hold by construction. A figure may never stall on the same
  cell for two matrices. Rotation rules are only ever attached to figures whose
  orientation is visible — a rotating square would be unanswerable.
- **`lib/generators/mathEquations.ts`** — builds systems the way the official
  exercises are built: pick a pivot letter, define the others in terms of it,
  then add one closing equation that pins the pivot. Uniqueness is never
  assumed — every candidate is brute-forced over the full 1–20 domain and
  rejected unless it has exactly one solution.
- **`lib/generators/latinSquares.ts`** — difficulty is *measured*, not guessed.
  A guess-free propagation solver records which deductions the question cell
  actually depended on, and the length of that dependency chain is the
  difficulty: low = 1, medium = 2–3, high = 4+.

## Development

```bash
npm test          # generator property tests
npm run typecheck # tsc --noEmit
npm run build     # production build
npm run lint
```

The tests are where correctness lives. They assert, over many seeded
generations, that no figure ever leaves the matrix or overlaps another, that
every equation system has exactly one solution in range, that every Latin square
is solvable by pure elimination at the requested depth, and that the same seed
always produces a byte-identical question.

### Inspecting generated questions

```bash
npm run preview -- latin high 2      # ASCII preview of Latin Squares
npm run preview -- math medium 2     # equation systems + derivations
npm run preview -- figures high 1    # figure series + solution paths
npm run preview -- stats             # difficulty distribution check
```

To inspect the rendered artwork without opening a browser, rasterize a real
question (pure-stdlib Python, no dependencies):

```bash
python scripts/render_glyphs.py                          # every figure at 4 rotations
npx vite-node scripts/preview.ts json high | python scripts/render_question.py
```

Both write PNGs to `scripts/out/`.

### Setting up the support page

`/support` is the "Buy me a coffee?" page. Everything it shows comes from
[`lib/support.ts`](lib/support.ts):

- **`UPI_QR_SRC`** — the QR people actually scan, currently
  `public/upi-qr.jpeg`. Any size, aspect ratio or format works: the image is
  rendered `object-contain` inside a square, so swapping the file is the whole
  job. (`public/upi-qr.png` is the original grey PLACEHOLDER stand-in, now
  unused — safe to delete.)
- **`UPI_ID`** — the virtual payment address, shown as copyable text under the
  QR and used to build the `upi://` deep link. It is `null` until you fill it
  in, and while it is null the page shows only the QR rather than printing a
  fake address beside a working code.
- **`CONTACT_EMAIL`** — the address on the "or just say hello" card.

The link appears in the header on every page, on the dashboard once you have
answered at least one question, at the bottom of a practice session after ten
answers, on the exam **results** screen, and on the official-links page. It is
deliberately absent from a running exam and from any live question.

## Layout

```text
app/                     routes: dashboard, practice, exam, rules, replay,
                         resources, support, login
components/
  questions/             one view per task type + a dispatcher
  render/                SVG figure catalogue, 4×4 matrix, 5×5 Latin grid
  charts/                stat tiles + daily volume chart (validated palette)
lib/
  generators/            the three generators — where fidelity lives
  rng.ts                 seeded PRNG and the seed format
  rules.ts               task-type reference shown on the /rules pages
  attempts.ts            Supabase reads/writes + offline buffering
  stats.ts               dashboard aggregation
  support.ts             UPI ID, contact address and QR path for /support
supabase/migrations/     schema + row level security
tests/generators/        property tests
scripts/                 preview and rasterizing tools (dev only)
```
